# Negotiated fixed-parameter discovery adoption

Status: PROPOSED. Planning only. Acceptance is required before dependency implementation. No app adoption or checking-pipeline START is granted.

## Root cause

At connect-automate main d68b25f8390a449126ae54bda2b156c836be7418, generic discovery always decodes the strict legacy v2 manifest (src/connect_automate/connect.py:1212-1214). _ParameterDeclaration (:167-172) and CapabilityParameter/public_dict (:417-435) have no fixed_value presence/value. The capability converter (:1054-1061) consequently cannot retain fixed identity. _validated_parameters (:1333-1389) validates caller values only, and is used by both new request construction and persisted restoration (:1517). Simply extending that shared validator with current-declaration fixed binding would risk rejecting or rebinding an already frozen request after rotation.

These are missing adoption surfaces, not proof that today's legacy paths are broken. The shared contract is landed; the dependency must implement its own real discovery and construction paths without redefining provider idempotency.

## Required change surface

1. src/connect_automate/connect.py: keep the strict legacy decoder; derive a separate negotiated decoder from the same legacy declaration/validation owners. Preserve all existing type, identifier, boundedness, unique-member, identity-attribution and closed-object checks. A fixed member requires required=true, its declared primitive type and the canonical request bounds. Presence preserves empty string, zero and false; null/nested values reject. No second copy of legacy validators.
2. _discover_capabilities and its public discovery wrappers: add explicit caller opt-in for fixed-parameters-v1, default off for compatibility. Opted-in v2 discovery sends the exact feature request header. Decoder selection and readiness follow the canonical shared exchange owner under the accepted PR65 amendment, once its executable revision is reviewed and landed. Auth, registered identity matching, time budgets, limits, registration safety, endpoint validation, conflicting-instance handling and entitlement behavior remain owned by their existing paths. v1 discovery and registered GET-only reconciliation stay unchanged.
3. Discovery delegates freshness and legacy admission to the canonical shared policy; no dependency-specific exception or duplicate header rule. No response reuse; rediscovery makes a fresh authenticated request. The dependency does not cache manifests today. Producer conformance and consumer admission are different obligations. A compatible legacy response exposes only its actually advertised capabilities, never a fabricated classifier, COI capability or fixed identity.

### Remaining change surface

4. CapabilityParameter and _generic_capabilities/public_dict: retain fixed-member presence separately from value. A legacy public dictionary omits fixed_value; a negotiated one preserves its exact admitted value, including falsy values. Internal absence representation must never leak into the public dictionary or request. Metadata transport is generic; no hardcoded Invoice Processor provider, bundle algorithm or classifier policy enters this dependency.
5. New request preparation: one binding owner consumes the explicitly selected declaration, fills an omitted fixed value before freezing, preserves ordinary required/editable parameters and rejects a wrong-typed or conflicting supplied value under the existing PARAMETERS_INVALID contract. No prompt is needed for a fixed parameter. Declaration matching uses typed value equality. Only new-request preparation routes through that owner, before intent/request freezing; do not bypass existing source/media/hash/confirmation gates. restore_capability_job, restore_persisted_capability_job and restore_registered_capability_job are restoration paths and must not fill or bind from live discovery. ConnectV2CapabilityInvoker.invoke restores a frozen durable action through restore_capability_job (automate_connect.py:252-262), so it is not a new-request binding entry point even on its first resumed dispatch. Missing or stale fixed identity in a frozen action is never repaired by consulting a newly discovered declaration. The caller that originally selects and freezes a new action must bind its admitted declaration before persistence; retrofitting old actions is outside this slice. Existing new-request normalization for ordinary integer parameters is preserved; it does not rewrite persisted requests.
6. Persisted request restoration: never inject missing fixed values, compare with the newly advertised bundle or reserialize stored request_json. Restore validates existing wire integrity and capability/source identity through the inherited owners, preserving the frozen bytes and old admitted parameter identity. Where declaration-specific validation is needed, use the recorded admission declaration supplied by the caller, never a replacement live manifest. Persisting that declaration belongs to the caller adoption; GET-only registered reconciliation does not acquire a new declaration. Provider admission still decides replay versus conflict or failed restart under its recorded/current identity. A stale declaration is not permission to create new work. Caller selection/generation persistence belongs to Watcher adoption, not this library.
7. One v2 refusal semantic owner enforces the canonical FIXED_PARAMETER_MISMATCH constraint in both actual HTTP-error and terminal-status decoding. _ErrorEnvelopeV2/_http_error_v2 and _JobStatusV2/ConnectV2Client._job_update must consume that owner: a fixed-parameter refusal requires retryable=false, and retryable=true is an invalid provider response. Reject the invalid combination before it becomes ConnectError or JobUpdate; never silently normalize it or expose it through a generic retryable fallback. A malformed fixed-parameter refusal must not authorize automatic resend, including an HTTP 5xx envelope. Valid refusals retain their code and false retryability without message parsing or fabricated results. Preserve ordinary error retryability and v1 decoding; specialize v2 semantics rather than changing the generic _JobError owner for all protocols. Watcher's deferred/classifier_bundle_unavailable mapping remains its separately reviewed I-state amendment.
8. Tests: tests/test_connect.py for decoder/DTO/preparation/restore; tests/test_windows_connect.py for shared discovery on Windows; tests/test_automate_connect.py for the preparation boundary where applicable. Consume immutable shared artifacts through a verified pin or checked copies with full hash receipts. A compact ownership guard proves decoder differences are limited to the extension. Generic conformance consumes generic schema/vector rules; classifier-specific declaration policy and provider admission events remain with their named owners, not a vendor-specific generic-library validator.

### Single frozen invocation contract owner

The selected invocation is frozen once, before persistence. Alongside its admitted bound parameter values, its durable action metadata records `required_manifest_features: ["fixed-parameters-v1"]` when preparation used a negotiated declaration. This bounded optional field permits only that exact feature, with no duplicates. Absent or empty metadata represents existing legacy actions; invalid types, unsupported tokens and conflicting metadata reject at that same frozen-action boundary. It is action metadata, never an extra v2 job-request member or a provider digest policy.

The creation/binding owner produces this metadata; serialization, persistence and `_InvokeRequest` parsing preserve it unchanged. `ConnectV2CapabilityInvoker.invoke` passes the recorded requirement to its discovery call for that action only, before selecting and restoring the capability. Actions without it continue default legacy discovery. Do not infer the requirement from parameter names/values, app labels/versions or live discovery; do not use a global opt-in switch. All consumers of this concept route through the frozen invocation owner.

Discovery retains the verified acknowledged feature set with the catalog and each declaration/public DTO used for selection. This provenance comes only from the authenticated, validated response under the canonical exchange owner; requesting a feature is not acknowledgment. Preserve its association with the same registered provider and discovery response through catalog conversion and selection. Never infer it from capability id/version, app name/version, runtime instance identity or fixed-parameter presence. Wrong, malformed, ambiguous or unsolicited acknowledgment remains a rejected response under the shared owner.

The frozen invocation/selection owner conjoins the validated persisted `required_manifest_features` with that catalog's verified acknowledged feature set before restoration or dispatch: every required feature must be acknowledged by the selected provider response, in addition to existing capability id/version/instance matching. A missing requirement acknowledgment yields `CAPABILITY_NOT_FOUND` with zero POSTs, even when a valid unacknowledged legacy catalog advertises the identical capability id, version and runtime instance. Provider-side classifier suppression cannot replace this generic consumer gate. An absent or empty action requirement preserves existing legacy selection of actually advertised capabilities.

Rediscovery cannot rebind saved fixed values or change saved request/replay identity. No legacy replacement request is sent for an unmet feature requirement. A later admitted bundle does not rewrite an older action; provider admission/replay retains its existing identity semantics. Recorded negotiation metadata and verified acknowledgment do not grant entitlement or fixed-value compatibility by themselves.

## Assumptions and blockers

- This is a dependency adoption contract proposal, not accepted implementation. Existing session owns preparation of this plan; implementation ownership and acceptance must be explicit.
- Shared pin is the landed PR64 tree, not a mutable main snapshot. Generic validation delegates to canonical owners; classifier-specific semantic qualification remains outside the dependency.
- Provider and Watcher adoption contracts must separately pin this dependency's reviewed implementation and prove their actual paths. Fixed-value presence transported to a public DTO does not prove an app renders it without a prompt.
- Legacy default discovery is intentionally preserved. Opted-in caller adoption must handle providers not satisfying the negotiated response rules visibly through existing unavailable outcomes, not fabricate compatibility.

Before implementation, record exact baseline/source pins and shared artifact hashes. Declare each fail-first regression and expected failure before running it. Use public synthetic manifests/artifacts and isolated entitlement fixtures; no live licence or documents.

- Decoder: valid fixed declarations; unknown fields; mixed valid/invalid capabilities; required=false; null/nested values; type crossovers; empty string/zero/false; string1000/1001; integer +/- (2^53-1) bounds; integral/nonintegral numbers; undeclared/missing/duplicate names; legacy decoder still rejects fixed_value.
- HTTP: exact token/ack, no request, unsupported/mixed-case token, missing/unsolicited/wrong/duplicate ack, header-name case; both request orders; no-store/Vary preservation; stale rediscovery after bundle replacement; response app/instance mismatch; bounded/duplicate JSON and existing entitlement/timeout paths. Count actual requests, not mock dictionaries alone.
- DTO/preparation: omitted fixed value is filled once from selected declaration, falsy values survive public serialization and request creation, matching typed integral values admitted, wrong-type/conflicting values rejected, nonfixed required inputs remain required, extra caller keys reject; inspect actual frozen request bytes.
- Frozen invocation boundary: serialize/reload the durable requirement before actual `ConnectV2CapabilityInvoker.invoke`. (1) A valid unacknowledged legacy catalog advertising the same classifier id/version AND runtime instance must yield CAPABILITY_NOT_FOUND with zero POSTs for a required-feature action, despite otherwise matching selection. (2) A correctly acknowledged valid provider passes selection with the frozen requirement and original bound values/request identity, including bundle rotation; provider admission/replay decides compatibility without rebinding. (3) Pre-feature invoice/COI actions without the requirement retain legacy selection and hand-off of only actually advertised capabilities. Losing acknowledgment after freezing must refuse without a legacy replacement. Observe real invocation and POST counts, not only constructed helper DTOs; prove verified acknowledgment provenance survives catalog/declaration/public DTO conversion.
- Restore: unchanged accepted-job requests before/after advertised rotation restore exact bytes and old bundle; no new discovery value is substituted. Test changed request identity through the existing owner without introducing a universal numeric-spelling decision. Missing required frozen values remain malformed; restoration never repairs them. Registered GET-only reconciliation continues without a manifest. At the actual ConnectV2CapabilityInvoker.invoke boundary, replay the same durable action/job id before and after fixed-value rotation; no newly discovered value may be inserted, substituted or POSTed as a changed request. Cover an older frozen action missing the new required identity: explicit refusal/unavailability, no repair and no rewritten dispatch. Unit restoration helpers alone do not prove this boundary.
- Refusal: direct canonical-schema checks remain supplementary. At actual HTTP-error decoding and terminal failed-status polling, a valid FIXED_PARAMETER_MISMATCH/retryable=false retains its permanent outcome; the same code with retryable=true must fail as an invalid provider response and cause no automatic resend. Cover HTTP 409 and 5xx, malformed retryability types/missing members, failed terminal status, and an unrelated valid generic error whose retryable=true remains unchanged. Remove the v2 semantic constraint as a mutation: the real HTTP and polling probes must fail, rather than only a shared-schema test. This is a required fail-first runtime regression before future dependency implementation, not current runtime proof. Watcher mapping is not exercised or claimed here.
- Mutations: disable ack gate, erase falsy fixed value, allow supplied override, compare restored request to current bundle, reserialize or normalize stored bytes, remove either refusal constraint, drop the persisted negotiation requirement, fail to forward it in actual invocation, drop the verified-acknowledgment selection gate, or substitute requested features for verified acknowledgment. The three real invoker scenarios must kill those boundary mutations. Each must be caught at its actual relevant owner; static-only mutations are not substitutes for client path tests.
- Run focused affected tests and Ruff first. Preserve Windows discovery tests and existing tests/test_connect_automate_boundary.py. Broader required checks follow the repository workflow if configured; record absence honestly. Shared suite evidence may be reused only with verified identical artifact hashes.
